# 手術排程與 FU 追蹤系統

這是綁定 Google Spreadsheet 的 Google Apps Script 專案。版本
`2026.07.28.3` 保留五個責任清楚的模組，並將日常同步改為單表／單列
快速路徑：

- `code.js`：入口、選單、設定與共用工具。
- `sheet_model.js`：欄位模型、格式、日期區塊與時間正規化。
- `calendar_sync.js`：Calendar 事件生命週期與 V2 同步索引。
- `workflows.js`：FU／月表快照、月份模板與排序。
- `annual_archive.js`：私人整檔備份與永久年度封存。

Sheet 是唯一臨床資料來源；同步方向是 Sheet → Google Calendar。

既有月份刀表若仍使用 `2026/8/13 Thu` 形式的文字日期，系統會嚴格
核對日期與星期後視為刀日標題；「安裝／修復系統」可安全轉成正式日期
格式並補上 `◆ 刀日`。孤立病人列、日期與 Event ID 混合列等真正衝突
仍會停止處理。

## 資料表

### FU

標準可見欄位：

`病歷號、姓名、TEL、醫院、Tag、Condition、日期、Plan、心得`

正式系統欄只有：

`CalendarEventId`

- 有有效日期，且病歷號或姓名至少一項非空白，就建立或更新自己的
  全天 Calendar 事件；FU 不使用時間欄。
- 清空日期，或同時清空病歷號與姓名，會刪除該列自己的事件。
- 尚未填日期且沒有 `CalendarEventId` 的 FU 草稿不進入 Calendar 同步鎖或
  待重試佇列；快速連續編輯未排程資料不會產生「同步忙碌」note。
- Calendar 標題固定保留三個位置：
  `病歷號 | 姓名 | Condition`。
- Tag 建議選項為：
  `FU、Complication、CATA、Cornea、Retina、Plasty、Neuro、Refraction、Suture IOL、IVI`；
  仍允許自訂文字。
- Tag、心得與自訂欄不寫入 Calendar。

### 月份刀表

月份表使用 `YYYYMM` 名稱。標準欄位：

`日期／報到時間、醫院、病歷號、姓名、TEL、GA、側別、診斷、Grade、術式、Plan、IOL、IOL Target、IOL Final、Axis、心得、空白分隔欄、SN、CDE、Energy Time、Energy %、屈光數據、CalendarEventId`

`IOL、IOL Target、IOL Final、Axis、SN、CDE、Energy Time、Energy %`
預設使用純文字格式，因此可直接輸入 `+20.0`、前導零或其他符號，不必
在前方加單引號。格式升級不會推測或補回既有資料中已經消失的 `+`。

- 日期標題列由「第一欄是 2000–2099 年完整日期，且 `CalendarEventId`
  空白」判定；醫院空白時會補為高榮。
- GAS 會在日期標題列的「病歷號」格顯示固定 `◆ 刀日`。此標記是可見狀態，
  正式判斷仍以日期及 Event ID 為準，因此第一欄可以直接修改日期。
- 日期標題的第四欄以後可輸入刀日備註；不影響灰底或區塊判定，也不寫入
  Calendar。完整日期與非空白 Event ID 並存時列為衝突，不自動改期。
- 病人列第一欄只放報到時間，歸屬於上方最近的有效日期／醫院標題。
- 相同日期與醫院可以有多個獨立區塊；每個標題及其下方病人列各自保留，
  不會在整理或封存時自動合併。
- 有有效日期區塊，且病歷號或姓名至少一項非空白，就建立或更新事件。
- GA、空白時間及 `PM` 等文字建立全天事件；可辨識時間建立 30 分鐘事件。
- 月表 Calendar 描述包含醫院、TEL、Plan、GA 與必要的時間備註。
- `CalendarEventId` 隱藏且以警告式保護。

## 時間輸入

月表及 FU→月表視窗共用同一個時間正規化器：

- `0800`、數值 `800` → `08:00`
- `830` → `08:30`
- `8:00` → `08:00`
- Sheets 時間值 → `HH:mm`
- `PM` 等文字保留，建立全天事件並寫入描述
- `2460`、`25:00` 等無效時間加 note，停止該列同步

單格輸入、多格貼上及整列貼上都會處理。FU 事件固定為全天；IVI 的
「下次回診時間」是日期欄，兩者都不套用上述時間轉換。

## Calendar 事件生命週期

FU 與月表共用同一套服務：

1. 建立事件。
2. 以該列 `CalendarEventId` 更新事件。
3. Event ID 404 時重建。
4. 刪除事件；404 視為已刪除。
5. 建立／更新後回讀驗證標題、描述、日期時間與事件顏色。
6. 發現重複 `CalendarEventId` 時標記所有相關列並停止那些列的同步；其他
   Event ID 唯一的列仍可個別同步。

每列只管理自己的 `CalendarEventId`。系統不以病人內容搜尋 Calendar，也不做
Calendar → Sheet 反向同步。

事件配色由單一規則決定，優先順序如下：

- FU：色彩 ID 8，灰色 `#E1E1E1`。
- 月表 GA：色彩 ID 4，珊瑚紅 `#FF887C`，維持全天事件。
- 月表可解析為 `HH:mm` 的明確時間：色彩 ID 10，綠色 `#51B749`。
- 月表空白、`AM`、`PM`、待通知等非明確時間：色彩 ID 2，淡綠
  `#7AE7BF`。
- 無效時間不更新事件，保留原事件並以 note 提示。

同步失敗或衝突時，系統會在該列可見的病歷號儲存格加入 note；病歷號空白時
改放在姓名儲存格。可見 note 只顯示安全、可操作的摘要，不顯示 Event ID 或
完整 API 錯誤。既有人工 note 會保留，成功同步時只移除系統訊息區塊。時間格式
錯誤則顯示在該列時間儲存格。

## V2 同步索引與原生列操作

`CALENDAR_ROW_REGISTRY_V2` 儲存在 Script Properties：

- 保存原始 Event ID、表單種類、sheet ID、列號、日期區塊及內容雜湊。
- 不保存病歷號、姓名、診斷、Condition、TEL 或 Plan 原文。
- FU 掃描採整表批次讀取；正式索引的分段以一次 `getProperties` 回讀、
  一次 `setProperties` 寫回，不再逐分段呼叫遠端服務。
- 月份整理與 FU 整理只比對目標分頁和既有已驗證索引；排序不會新增或修改
  Event ID，因此不重讀其他月份。目標分頁重複 ID、pending、內容漂移或
  索引缺漏仍會安全停止；跨表完整診斷由「檢查同步健康」負責。
- 確實發生列位移時才刷新受影響分頁索引，並直接重用前置檢查與排序後已
  讀取的資料；原本已排序時不寫索引、不插入暫時欄。
- 年度封存表也以不含臨床原文的 archive entry 寫入索引，使日常同步可直接
  使用同一份全域唯一性基準；封存列仍完全排除 Calendar 更新。
- 單列 onEdit、日期標題區塊同步及 FU→月表建立事件時，會先核對目前分頁的
  Event ID 集合與 V2 索引。索引完整、沒有 pending 且集合一致時，只讀目前
  分頁，不掃描其餘 FU／月份表；任何不一致都自動退回全表 Event ID 掃描。

支援：

- 完整列拖拉至另一日期／醫院或月份：更新原事件。
- 同區塊內重新排序：只刷新列號，不呼叫 Calendar。
- 原生刪除單筆或多筆病人列：刪除已從所有管理表消失的事件。
- API 刪除失敗：保留 pending-delete，供「同步待處理變更」重試。
- 只搬動可見儲存格、手動清除 Event ID：列為衝突，不刪除舊事件也不建立新事件。
- 刪除日期標題而留下病人：列為衝突，不自動把整區改期。
- 刪除整張分頁：永遠不批次刪除該分頁的 Calendar 事件。

onEdit 與 onChange 各安裝一個。onEdit 會批次讀取貼上範圍、一次處理
`0800 → 08:00`、notes 與列格式，再以短等待鎖同步受影響列；同一份月份
區塊掃描會在列判定與 Calendar 同步間重用，不在日常路徑列舉整個 Calendar。
onChange 將拖拉與刪列需求
合併到不含病患原文的 pending queue。鎖正忙時不再等待 20 秒後失敗，而是
立即合併排隊，並建立一個約一分鐘後執行的一次性重試觸發器。第一次短暫
鎖衝突不寫 note；只有自動重試後仍無法完成，才保留具體原因與下一步的
系統 note。重試成功會清除已解決的系統 note，人工 note 不受影響。
系統不建立固定週期背景掃描；Google 未送出事件、或自動重試仍失敗時，
可使用「修復選取列同步」或「同步待處理變更」立即處理。

## FU 與月表互轉

兩邊都是一次性、互不連動的快照。

### 月表加入 FU

只複製：

`病歷號、姓名、TEL、Condition、Plan、心得`

FU 的醫院、Tag、日期與 `CalendarEventId` 留空。建立前分成「完全相同」
與「病歷號＋Condition 相同」兩級警告；確認後仍可建立。因新列沒有日期或
Event ID，成功複製不重建 Calendar 索引，並直接跳到 FU 新列。

### FU 排入月表

- 常用區固定顯示月份、日期區塊、醫院、報到時間。
- 開啟視窗時只取得月份名稱，不再預先掃描所有月份內容；選定月份後才載入
  該月的刀日區塊。
- 診斷、術式、Grade、IOL、Plan、心得放在可摺疊的進階區。
- 日期、醫院、時間與手術結構全部取自視窗，不沿用 FU 追蹤日期或事件 ID。
- FU Condition 以 note 保存，避免解析未涵蓋的內容遺失。
- 新列附加在日期區塊末端，不自動排序。
- 回讀成功後立即同步 Calendar。
- 10 分鐘 request token 防止網路重送；重送會以 Event ID、內容雜湊及日期區塊
  重新定位既有列，不依賴可能因排序而改變的列號，再只重試 Calendar。
- 疑似重複仍可確認建立，因為同一病人可能有多次手術。
- 同日期、同醫院有多個區塊時，清單會附標題列號；送出前重新驗證列號、
  日期與醫院，避免寫入錯誤區塊。
- 建立時重用同一份目標月掃描結果完成重複檢查、區塊定位與新列寫入；
  Calendar 同步直接使用已驗證的新列內容，成功後只刷新該月份的同步索引。
  一般既有月份流程因此不再反覆讀取整張月表。

## 月份模板與排序

`建立新月刀表`：

- 建立或初始化指定 `YYYYMM`。
- 自動加入當月第 2、4 個星期一及星期四的高榮日期區塊。
- 每區塊保留 5 列空白輸入列。
- 已永久封存的月份不能直接重建；必要時須從私人整檔備份人工復原。

`選取列新增刀日`：

- 在目前月表選取列前插入一個刀日標題，不覆寫原資料，也不額外插入空白列。
- 只詢問日期；日期必須屬於目前月份，醫院先設為高榮，之後可手動改為聯醫。
- 自動填入 `◆ 刀日`、日期格式、灰底、字型及驗證。
- 若插入位置分割既有區塊，會先顯示受影響資料列及有效病人數；確認後立即
  更新下半段病人的原 Calendar 事件。
- 相同日期／高榮已存在時會警告，但確認後仍可建立獨立區塊。

`整理月刀表`：

- 日期遞增。
- 同日依高榮、聯醫排序。
- 同一日期／醫院的獨立區塊依原標題順序穩定排列，不合併。
- 區塊內明確時間遞增，文字時間其次，空白最後；同組維持原順序。
- 保留整列資料、公式、notes、驗證、格式、自訂欄及 Event ID。
- 使用暫時排序鍵及 Sheets 原生 Range sort，一次搬動完整資料列，不再逐列
  清空及重寫；每個區塊至少補足 5 列空白輸入列。
- 排序前後核對資料、公式、notes 與 Event ID；驗證失敗時以原順序鍵還原。
- 排序後只刷新目前月份的 V2 索引；已是正確順序時直接結束。
- 本操作不呼叫 Calendar API。

`整理FU日期`：

- 由早到晚排列有效日期，空白日期置底，同日維持原相對順序。
- 整列保留自訂欄、公式、notes、格式及 `CalendarEventId`。
- 使用一次 Sheets 原生 Range sort；不再為每筆 FU 分別重寫十多種格式屬性。
- 排序前後以資料／公式／notes 指紋核對；驗證失敗時自動回到原順序。
- 原本已是日期遞增時直接重用前置掃描，略過第二次資料／formula／note
  回讀、暫時欄、原生排序、列高調整及索引寫回。
- V2 索引的單表 metadata 另存不含臨床原文的 `fastFingerprint`。指紋相符時，
  排序前置檢查只需一次表格資料讀取與一次 SHA-256，不再逐列計算內容雜湊；
  舊索引缺少指紋或內容漂移時自動回到完整核對。
- 非空白無效日期會停止排序；本操作不呼叫 Calendar API。

## 日常效能設計

- 欄名、月份區塊及 Event ID 掃描結果只在同一次執行內重用，不建立可能因
  使用者調整欄位後失效的跨執行欄位快取。
- 月表加入 FU 不呼叫 Calendar、不重建同步索引，FU 欄名只解析一次。
- FU 排入既有月份只掃描目標月份一次；Calendar 建立／更新後的索引刷新會
  重用同一份全域 Event ID 檢查。
- 日常排序的 Script Properties 索引採整批讀寫；純排序不再逐一刪除、重建
  每張工作表的索引分段。
- 多列貼上時間及列格式採連續區段批次操作；onEdit 只格式化這次實際編輯到
  的標準欄，只有長文字欄才調整列高，只有日期／醫院／刀日標記相關欄才檢查
  刀日標題。
- 每個選單動作只記錄功能名稱、成功狀態與執行毫秒數至 Apps Script
  execution log；重要操作另記錄前置檢查、Sheet 寫入、Calendar 與索引更新
  的階段耗時，不記錄病歷號、姓名或其他臨床原文。
- 「檢查同步健康」、永久封存及私人整檔備份仍以完整性優先，因此預期比
  日常新增、排序及單列同步耗時。

## 永久年度封存

`彙整舊月刀表`：

- 可選擇一個以上、嚴格早於目前月份的月表；跨年度時分別加入
  `刀表封存_YYYY`。
- 依月份、日期、醫院及報到時間遞增，保留空刀日、公式、notes、格式、
  自訂欄與 `CalendarEventId`，移除每區塊空白輸入列。
- 年度表的 `CalendarEventId`、`ArchiveSourceMonth`、`ArchiveRowType`
  隱藏且受保護；臨床區為警告式保護，仍可人工編輯。
- 後續追加同年度月份時不覆寫既有月份或人工修改；若隱藏結構欄遭破壞，
  系統停止，不猜測資料。
- 封存表不參與 onEdit、onChange、批次同步、初始化或格式修復，但其 Event ID
  仍納入全域重複診斷；既有 Calendar 事件完全不更動。
- 寫入前先在擁有者 My Drive 建立私人整檔備份並回讀驗證。只有私人權限、
  年度表內容及 Event ID 全部驗證成功後，才永久刪除來源月份分頁。
- 交易中斷時保留不含病患原文的交易檢查點並暫停自動同步；再次執行同一選單
  會安全續跑。來源尚未開始刪除時，暫存變更會自動回復。
- 一般選單不提供解除封存；需要復原時由私人整檔備份人工處理。

可見分頁順序固定為：

`FU → IVI → 有效月份降序 → 年度封存表 → 其他分頁`

一次性舊遷移備份分頁清理已完成；私人整檔備份保留於擁有者 My Drive。

## 欄位與格式

- 所有自動化依第 1 列唯一且完全相符的欄名定位，不依固定欄位位置。
- 標準欄可自由排序；缺少欄位才附加至最右側。
- 可新增具唯一非空白名稱的自訂欄；自訂欄不跨表複製、不寫入 Calendar。
- FU 與月份標準臨床欄及系統欄使用 Arial 10。
- 表頭中灰、黑字、粗體；日期標題淺灰。
- GA 淡紅、OD 淡綠、OU 淡紫。
- Plan 含 `!` 為淡紅、含 `APPLY` 為淡綠、含 `#` 為淡黃；優先順序為
  `!` ＞ `APPLY` ＞ `#`。
- 長文字欄換行。既有 FU／月表的欄寬不會被安裝、初始化、排序、onEdit 或
  FU ↔ 月表操作重設；只有新建表會套用預設。需要恢復建議值時，明確執行
  `維護工具 → 套用所有 FU／月表建議欄寬`，自訂欄寬不受影響。
- 建議緊湊欄寬（px）：日期／報到時間 115、醫院 58、病歷號 76、姓名 72、
  TEL 96、GA 42、側別 46、Grade 82、IOL 96、IOL Target 80、
  IOL Final 76、Axis 52。FU 套用其中的醫院、病歷號、姓名與 TEL。

## 安裝與維護

V2 同步架構升級已完成；一次性的「預覽同步架構升級」與
「執行同步架構升級」已從正式選單及執行程式移除。既有 Script Properties
Script Properties 備份與 Git 歷史保持不變。FU 時間欄與月份刀日標題升級也已
完成，其四個預覽／執行選單及專用程式已退役。

`安裝／修復系統` 先檢查同步索引；有待處理變更、衝突或未完成封存交易時
停止，不會覆蓋同步基準。通過後才初始化格式、安裝觸發器、建立索引及排列
分頁；不會自動批次重寫全部 Calendar 事件。

日常選單只保留：

`檢查同步健康` 會以唯讀 Calendar API 同時比對目前資料、V2 索引與實際事件：

- 沒有待處理項目或衝突時，更新「同步健康報告」後自動隱藏。
- 發現待處理項目、同步失敗或衝突時，自動顯示報告。
- 檢查事件是否遺失，以及標題、描述、日期、時間或顏色是否漂移。
- 檢查月份表混合列、孤立病人列、跨月份日期及刀日標記；合法的重複日期／
  醫院區塊不列為衝突。
- 分頁清單漏列時會用 Event ID 單筆回讀，避免誤判為遺失。
- FU、有效月表與年度封存都沒有來源的系統格式事件會列為待確認殘留；
  人工建立且不符合系統標題／描述結構的事件不會被列入刪除範圍。
- 報告只記錄工作表、列號、狀態、說明及 Event ID 雜湊，不寫入病患原文或
  原始 Event ID。
- 報告是最近一次檢查的快照，不是持續即時監控。

`同步待處理變更` 才會修改 Calendar。它會更新漂移事件、為 404 事件重建，
並在顯示數量且取得確認後刪除已消失資料列或無來源的系統事件。年度封存事件
只作合法來源辨識，不更新也不刪除。完成後會重新整理健康報告；若所有問題均
已排除，報告會再次自動隱藏。

`修復選取列同步` 是局部快速修復：

- 可選取 FU／月表病人列；選取刀日標題時會納入該區塊病人。
- 若選取列的 Event ID 重複，預覽會自動納入所有相關列。
- 預覽會列出 Sheet 預期日期／時間、目前 Calendar 日期／時間及建議動作；
  確認前不寫入。
- 可正規化時間、建立缺少事件、更新漂移、重建 404 事件、清除已解決的
  系統 note，或在只有一個穩定吻合事件時重新綁定 Event ID。
- 預覽後若列內容、同步索引或 Calendar 狀態改變，整次停止並要求重開預覽。
- 有多個候選時停止，不猜測；合法的同病人多次手術不會被合併。
- 本工具不刪除 orphan 或已消失資料列的事件；刪除仍由
  `同步待處理變更` 顯示數量並再次確認。

Calendar 建立／更新及回讀驗證成功後才提交 V2 索引。API 失敗會留下
`pendingSync`，pending queue 也會出現在同步健康報告；失敗狀態不會被誤記成
已完成。系統 note 只管理自己的前綴區塊，會保留人工 note，並顯示具體原因、
相關列、預定日期／時間及下一步。

若只存在舊分頁 `OP`，系統會停止並要求使用者手動改名為 `All`，不會自動改名。
